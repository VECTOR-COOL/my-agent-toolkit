# 記憶整理

只做**要不要升永久**的判斷。身份、確認、去重與後端讀寫以 [`my-memory`](../my-memory/SKILL.md) 與 [backends.md](../my-memory/references/backends.md) 為準。

```mermaid
graph TD
  Hit[本次採用的短期記憶] --> Meta{metadata 可讀寫?}
  Meta -->|否| Stop[停止，不升也不刪]
  Meta -->|是| W{weight 為 high?}
  W -->|否| Stay[留在短期]
  W -->|是| C{read_count 達 3?}
  C -->|否| Stay
  C -->|是| Ask[蒸餾並請使用者確認]
  Ask -->|同意| Perm[寫入永久並讀回]
  Perm -->|成功| Del[刪除該筆短期]
  Perm -->|失敗| Keep[保留短期]
```

## 計數放哪

放在該筆 Mem0 記憶的 metadata。欄位固定：

| 欄位 | 值 |
|------|----|
| `weight` | `high` 或 `normal`。沒有就當 `normal` |
| `read_count` | 整數。沒有就當 `0` |

搜尋相似度、排序不是權重，也不當讀取次數。工具不能讀寫 metadata 時，這次不計數、不整理，並說明缺 metadata。

## 權重

- `high`：使用者說重要或要長期留，或內容已是穩定偏好、身份事實、一直有效的決定。
- `normal`：任務脈絡、還會改的決定、沒說要長期留的。預設用這個。
- 不確定就 `normal`。閒聊、推測、憑證、token、金鑰、付款資料不標 `high`，也不寫進永久。

## 什麼算一次讀取

這筆記憶**實際被拿來回答或做決定**才加 1。同一則對話、同一筆只加一次。搜到但沒用，不加。

先讀目前的 `read_count` 再加。更新失敗就不要當成已加上，也不要整理。

## 何時整理

三項同時成立才整理：

1. 這筆是短期（Mem0）。中期索引、已經在永久庫的，不走這份。
2. `weight` 是 `high`。
3. 加上這一次之後，`read_count` **大於等於 3**。

使用者點名整理、但未達閥值：說出現在的權重與次數，問要不要這次例外升永久。例外仍要確認，不要默默做。

不整庫掃描。只處理本次讀到的，或使用者點名的那幾筆。

## 整理步驟

1. 蒸餾成一句去敏的穩定事實。還在改、或只是任務狀態，就拒絕升永久，短期留著。
2. 先查永久庫同一 `記憶鍵`。有就更新，不要新增第二筆。
3. 顯示：短期摘要、蒸餾後的永久內容、將刪除的 Mem0 id。等使用者同意。
4. 同意後先寫永久，讀回確認。
5. 永久寫成後**刪除**該筆短期。不要改成 `已過時` 留在 Mem0。
6. 永久沒寫成，不要刪短期。刪除失敗要明講；永久那筆已經在。

整理完，同一事實只留永久這一處。
