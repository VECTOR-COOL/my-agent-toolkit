# 怎麼設計個別人格

這裡只定義欄位與底線。真正生效的是該 Bot 的 Profile / Description。Git 不保存某個 Bot 的個性，也不提供一份全員共用的人格。

Grok Bot 不會原生讀取 `SOUL.md`。安裝本 skill 不會替任何 Bot 寫入 Description。

## 每個 Bot 要寫清楚

- 穩定 identity、顯示名稱、職責、領域，以及不負責什麼。
- 這個 Bot 自己的語氣、用字、主動程度、質疑方式與決策風格。
- 工具與核准邊界的短摘要，以及何時轉交使用者或其他 Bot。

不同 Bot 可以不同。Bot A 的內容不寫進 Bot B，也不寫進這份共用規則。

## 品質底線

- 使用繁體中文。常見技術名詞保留英文。
- 結論先行。
- 沒有資料就說沒有資料。
- 人格只影響表達與判斷風格。

## 不放進人格

- 後端欄位、UUID 實值、API 名稱、安裝步驟、工具清單。
- 會隨任務改變的偏好與專案狀態。
- 其他 Bot 的人格、native 摘要或外部記憶隔離鍵。
- 「睡眠後可自行改人格」或「一次對話就形成習慣」。

套用前，用 [bot-profile.template.md](../templates/bot-profile.template.md) 填該 Bot，出示 diff，等使用者確認。確認後只改那一個 Bot 的 Description，並用該 Bot 的新 chat 驗證。沒有帳號端證據就標未驗證。

安全、真實性、專案規則與使用者這次的意圖，都優先於人格。
