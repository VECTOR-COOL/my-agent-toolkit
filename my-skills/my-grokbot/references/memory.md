# 記憶歸屬

本檔只決定每個 Bot 的 native／外部記憶誰擁有、如何隔離、何時委派。Schema、欄位與整理演算法以這回合已載入的 `my-memory` 為準，不在這裡複製。

身份與 Grok Bot 讀寫細節，委派後以 `my-memory` 的 `grok-bot` 客戶端規則為準。

## 放哪裡

| 類型 | 去處 | 誰擁有 |
|------|------|--------|
| 這次任務進度、尚未確認的假設 | 這次對話 | 不寫入後端 |
| 該 Bot 的穩定工作偏好 | host native memory | 該 Bot。讀不回就不宣稱已儲存 |
| 可選的短中期事實 | 該 Bot scope 的 Mem0 | 外部，一個 primary owner |
| 可選的永久事實 | Notion Agent 記憶庫的指定 scope | 外部，可稽核 |
| 人格與行為邊界 | 該 Bot Profile | 不由記憶自動改寫 |

同一事實只有一個 primary owner。使用者明確要求遷移並核准精確內容時，才寫第二處。

## 何時讀外部記憶

1. 先用 host 已經給這個 Bot 的 Profile、對話與 native context。沒有官方讀回介面時，不聲稱讀過哪些 native memory。
2. 外部記憶預設關閉。這個 Bot 沒啟用，或任務不依賴對話外的舊偏好、決策、歷史，就不委派。
3. 新 chat 本身不是查詢理由。
4. 要查時先查永久記憶。夠了就停。不夠才查一次該 Bot scope 的 Mem0。
5. 一般範圍用該 Bot 的 UUID。UUID 不明就停止，不用顯示名稱，不讀別的 Bot。
6. 私人、全域或共享 scope 只有使用者這次明確指定才使用。工具不能排除其他 identity 時，停止並回報。
7. 舊記憶與目前 repo 或即時資料衝突時，以現行來源為準，並標記憶可能過時。
8. Mem0 命中當下的整理由 `my-memory` 做一次。睡眠不再做第二次。

## 何時寫

使用者說記住，或指定層級，才提案。先顯示 Bot UUID、正規化內容、primary owner、scope、層級與後端，等這次確認。

| owner | 做法 |
|-------|------|
| native memory | 依 host 能力寫或提出。不能讀回就標未驗證，不另外寫外部後端 |
| 外部記憶 | 依賴閘門、UUID 與 scope 仍有效才委派 `my-memory`，寫入一個後端並讀回 |

禁止保存完整對話、閒聊、推測、密碼、token、金鑰、付款資料，或未去敏的外部內容。記憶可以記下「哪類動作需要核准」，不能存成可重用的永久授權。

沒有通過依賴閘門或 identity 不明時，停止外部讀寫，不繞過 `my-workflow`。
