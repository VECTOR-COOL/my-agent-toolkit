# Mem0 外部記憶管理

## 使用原則

- 適時使用，不得隨機或每則訊息都搜尋記憶。
- 只有記憶能實質改善正確性、延續性或個人化時才讀取。
- 只有使用者明確說「記住」、「存到 Mem0」或明確同意時才寫入。
- 不得自動保存完整對話、短暫閒聊、推測、密碼、Token、API Key、付款資料或其他憑證。
- 記憶找不到或工具失敗時如實說明，不得補造記憶。

## 判斷是否讀取

在以下情況搜尋 Mem0：

1. 使用者要求回想，例如「你記得嗎」、「我們之前決定什麼」、「繼續上次的內容」。
2. 使用者明確要求使用 Mem0 或外部記憶。
3. 任務依賴過往偏好、限制、設定、專案決策或已完成進度，而目前對話沒有足夠資訊。
4. 新資訊可能與既有長期偏好或決策衝突，且查證能避免錯誤。

在以下情況不要搜尋：

- 問題是自足的一般知識、單次計算或純文字改寫。
- 目前對話已含完整答案。
- 記憶內容與任務無關，只會增加隱私暴露或雜訊。
- 使用者明確要求不要使用記憶。

只要記憶實際影響回答，就簡短揭露來源，例如「根據私人記憶」或「根據團隊記憶」。不必展示內部記憶 ID，除非使用者要管理該筆記憶。

## 選擇記憶空間

- 使用 Composio 中別名為 `私人記憶` 的 Mem0 連線處理個人偏好、習慣、私人設定、個人計畫與個人決策。
- 使用別名為 `團隊記憶` 的 Mem0 連線處理公司、客戶、共享專案、團隊決策、技術規範與 SOP。
- 問題同時涵蓋私人與團隊內容時，先說明需要跨空間搜尋並取得同意。
- 無法可靠判斷空間時先詢問，不得任意選擇或合併結果。
- 每次執行都從 Composio 回傳的連線資訊依別名選取帳號；不得永久硬編碼連線 ID。
- Mem0 查詢需要 user、agent、app 或 run scope 時，沿用既有記憶所使用的實體；有多個合理實體且無法判斷時先詢問。

## Composio 執行流程

1. 先使用 Composio 工具搜尋功能，以英文描述單一 Mem0 任務並建立新的 workflow session。
2. 確認 `mem0` toolkit 有 ACTIVE 連線，並依上述規則選取精確帳號。
3. 只使用搜尋結果回傳的正式 tool slug；缺少完整 schema 時先取得 schema，不得猜測參數。
4. 讀取優先使用語意搜尋；需要完整列舉時使用清單工具並處理所有分頁。
5. 執行工具時傳入指定 Mem0 account；不得使用另一個帳號的預設連線代替。
6. 搜尋結果不足時，可在相同 scope 使用清單或 entity 查詢交叉驗證；不得靜默切換 scope。

## 讀取記憶

1. 將使用者問題改寫成簡短、具體且不洩漏額外敏感資料的語意查詢。
2. 限制回傳數量，先取最相關結果；需要完整性時再分頁。
3. 比對時間、scope、metadata 與內容，排除陳舊或互相矛盾的記憶。
4. 以記憶作為可查證脈絡，不把單筆記憶視為永遠正確；若與使用者目前說法衝突，以目前明確說法為準並指出差異。
5. 只把完成任務所需的最少記憶帶入回答。

## 新增記憶

只有使用者明確授權時執行：

1. 先搜尋相同主題，檢查重複、近似與衝突記憶。
2. 將內容整理為單一、耐久、可日後使用的事實或決策；不要直接保存整段聊天。
3. 先確認私人或團隊空間及正確 scope。
4. 新增時優先使用同步處理；若回傳非同步 event，輪詢到成功後再繼續。
5. 寫入後重新讀取驗證，回報實際儲存的精簡內容與空間。
6. 若同一事實已存在，優先更新原記憶，不要建立重複項目。

## 修改與刪除

- 修改前顯示原內容與預計新內容，取得明確同意後再執行。
- 刪除前重新讀取目標，顯示所屬空間與摘要，提醒刪除不可逆，取得明確同意後再執行。
- 批次刪除必須列明篩選條件、預估數量與影響範圍；不得用空篩選或過度寬廣的條件。
- 完成修改或刪除後重新查詢驗證結果，不得只依 API 成功訊息判定。

## 敏感資料與品質

- 不得儲存憑證、驗證碼、私鑰、完整信用卡號或可直接登入帳號的資訊。
- 健康、法律、財務、身分識別與親密關係等敏感記憶，只有使用者明確指定內容與空間時才可寫入。
- 對推測性內容加以澄清；不能將助理推論保存成使用者事實。
- 偏好或決策改變時，更新舊記憶並保留必要的時間語意，避免新舊內容同時被當成有效。

## 回應格式

保持簡短透明：

- 有讀取：說明使用了私人或團隊記憶，以及與回答相關的摘要。
- 無結果：說明查詢的空間與 scope，並請使用者補充或選擇其他空間。
- 有寫入：逐條列出實際保存內容、空間及是否為新增或更新。
- 未使用：一般自足問題不必額外宣告「未使用記憶」。
