# Windows 儲存空間安全清理

## 核心原則

- 先只讀盤點，再提出清理清單；未取得明確授權前不得刪除。
- 將「能重新產生的快取」、「可重新安裝的依賴」、「應用程式資料」、「使用者檔案」分開處理。
- 不得只因資料夾名為 `Cache`、`Temp`、`build` 就判定可刪；這些名稱也可能是原始碼、正式產物或資料庫內容。
- 不得直接刪除磁碟根目錄、使用者家目錄、專案根目錄、Docker VHDX、Cursor 資料庫或其他廣泛目標。
- 每次清理皆記錄清理前後可用空間、成功與失敗項目、可否復原及重新產生方式。

## 工作流程

### 1. 只讀盤點

1. 取得磁碟總容量、已用容量、可用容量與使用率。
2. 掃描頂層資料夾、最大檔案及常見快取位置。
3. 不跟隨符號連結或 NTFS junction，避免循環與跨磁碟誤掃。
4. 記錄無權存取的資料夾；不得把掃描不到誤判為零容量。
5. 比較檔案加總與磁碟已用容量。差距明顯時，檢查系統還原、資源回收筒、稀疏檔／VHDX、權限或仍被程序開啟的已刪除檔案。
6. 大量並行掃描時使用能等待動態工作佇列完成的實作；不得讓 worker 在其他 worker 尚未加入子目錄前提前結束。

### 2. 分級並回報

用編號表格列出：項目、精確路徑、估計容量、安全性、影響及建議動作。

依下列順序分級：

1. **高信心快取**：套件管理器快取、Gradle `caches`、瀏覽器 Cache／Code Cache、Wrangler `tmp`、明確的網站執行期快取、舊暫存及 crash dump。
2. **可重建依賴或產物**：`node_modules`、可重建的 `dist`／`build`。說明需重新安裝或建置，不得併入高信心快取。
3. **應用程式管理資料**：Docker、Android SDK／AVD、IDE 狀態資料。使用官方工具及應用程式感知流程。
4. **使用者資料**：影片、下載、備份、壓縮檔、專案、資料庫。只提供資訊，除非使用者逐項授權。

對疑似重複的大檔先比較大小與時間；要宣稱「完全相同」時，計算完整 SHA-256。

### 3. 取得明確授權

- 讓使用者以編號或精確路徑選擇清理項目。
- 將新的、風險更高的候選項目視為未授權，不得因與已授權項目相鄰就一起刪除。
- 若目標仍不明確或會影響專案、容器、模擬器、聊天記錄或備份，停止並詢問。

### 4. 執行精準清理

執行前建立精確白名單並逐項驗證：

1. 解析成絕對路徑。
2. 確認位於預期磁碟與父目錄內，且不是磁碟根目錄或廣泛目錄。
3. 避免未解析的環境變數、glob 與字串拼接刪除命令。
4. 優先清空快取內容並保留目錄；網站快取保留 `.gitignore`、`.htaccess`、`index.php`、`web.config` 等保護檔。
5. 使用可重試的逐項刪除並記錄鎖定、拒絕存取及其他失敗，不得掩蓋部分失敗。
6. 清理指定磁碟的資源回收筒後，重新掃描確認；指令報錯不代表一定未清除。

## 應用程式專用規則

### 開發工具與網站

- 可清理已確認的 npm、Yarn、pnpm、pip、Composer 與 Gradle 快取；說明下次執行會重新下載。
- `.wrangler/tmp`、框架測試快取與明確的專案 `.cache` 可列為高信心候選。
- `node_modules` 只能在 lockfile 與套件來源可用時列為可重建項目，並另行取得授權。
- WAMP／WordPress 只清理已確認的執行期位置，例如 `wp-content/cache`、站台 `content/cache`、Laravel `storage/framework/cache`。
- 不得清理 `vendor/.../Cache`、`src/.../Cache`、`wp-includes/.../Cache` 或外掛內的 `Cache` 類別目錄；這些通常是程式碼。

### Docker

- 先執行只讀的 `docker system df`；Docker 未啟動時回報無法判定可回收量。
- 依使用者授權使用 Docker prune 類命令，明確區分 image、container、build cache 與 volume。
- 絕對不得把刪除 `docker_data.vhdx` 當成一般清理；那會移除 Docker 資料。
- prune 後若 VHDX 未縮小，再以正確的 WSL／VHDX compact 流程處理。

### Android

- 先用 `sdkmanager` 移除未使用的 system image／SDK，再用 `avdmanager` 刪除指定 AVD。
- 官方工具無法辨識舊資料時，才在核對 API 版本、AVD 使用狀態及精確目錄後直接刪除。
- 保留仍被現有 AVD 使用的 system image、NDK 與工作中的模擬器。

### Cursor

- 將 CachedData、Code Cache、GPUCache、舊 agent 版本與擴充套件暫存分開評估。
- `state.vscdb` 是 SQLite 狀態資料庫，不得在 Cursor 執行中修改或直接刪除。
- 「壓縮對話／Summarize」只減少上下文 token，不會縮小 `state.vscdb`。
- 需要縮小資料庫時：完全關閉 Cursor、備份 DB／WAL／SHM、只讀分析大記錄、保留聊天索引、在交易中精準刪除、執行完整性檢查，再用 `VACUUM INTO` 產生新檔；空間不足時改用其他磁碟。

## 驗證與交付

1. 重新取得磁碟可用容量，計算實際增加量，不以檔案邏輯大小取代實測。
2. 重新掃描清理目標，確認只剩刻意保留的保護檔或空目錄。
3. 列出未清除、被鎖定、權限不足及仍需人工判斷的項目。
4. 說明刪除是否可復原；快取通常不可復原但能重新產生，使用者檔案則不得如此假設。
5. 明確說明哪些重要資料未碰觸，例如原始碼、`node_modules`、備份、Docker、資料庫與影音。
6. 若磁碟仍低於約 10% 可用空間，指出風險並提出下一批候選，不得擴大既有授權自行清理。
