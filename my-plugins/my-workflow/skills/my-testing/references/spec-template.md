# 測試 SPEC 模板

放在目標專案 `docs/specs/testing-plan-spec.md`。通用條文若上游專案已有 SPEC，用連結引用，只寫本專案的差異。

```markdown
# 測試計畫規格

- 文件版本：v0.1.0
- 更新日期：YYYY-MM-DD
- 狀態：生效
- 相關：[`.agents/rules/testing.md`](../../.agents/rules/testing.md)（Agent 怎麼做；本 SPEC 定義「必須是什麼」）

## 1. 目的與範圍

| 項目 | 規定 |
|------|------|
| 執行環境 | <語言執行版本、伺服器、埠號> |
| DB | <本機庫；禁止 DDL；測試資料前綴> |
| 編排位置 | `tests/`、`tests/e2e/`、`scripts/` |

## 2. 測試分層（四層）

| 層級 | 回答的問題 | 工具 | 目錄 | 需要伺服器／DB／憑證 | 預算 |
|------|-----------|------|------|---------------------|------|
| Unit | 邏輯對嗎？ | <runner> | `tests/Unit/` | 否 | < 10 s |
| Smoke | 系統活著嗎？ | <runner> | `tests/Smoke/` | 伺服器＋DB | < 30 s |
| Scenario（整合） | 合起來對嗎？ | <runner> | `tests/Scenario/` | 伺服器＋DB＋憑證 | 分鐘級 |
| E2E | 使用者流程走得通嗎？ | Playwright | `tests/e2e/tests/` | 全部＋瀏覽器 | 分鐘級 |

### 2.1 煙測合約

1. 唯讀：只 GET／SELECT。
2. 匿名優先：不需憑證能驗的不要求憑證。
3. 伺服器沒起來是失敗，不是略過。
4. 看內容，不只看狀態碼。
5. 一個入口一個案例（data provider）。
6. 不用 skip 掩蓋失敗；真缺陷登記 `tests/known-debt.md`。

### 2.2 分層判斷

| 要驗的東西 | 層級 |
|-----------|------|
| 純函式、無副作用類別、靜態規則檢查 | Unit |
| 只確認站台沒壞 | Smoke |
| 需要 DB 或 HTTP 的資料流程 | Scenario |
| 需要真實瀏覽器行為 | E2E |

## 3. 版本與環境斷言

| 必查 | 斷言 |
|------|------|
| 專案版本 | 常數格式正確，且等於文件記載值 |
| DB 版本 | 常數格式正確且等於記載值；只讀 |
| 執行版本 | 在支援範圍內；自有程式碼無範圍外語法 |

## 4. 指令合約

| 指令 | 行為 |
|------|------|
| `scripts/test.sh unit` | 單元 |
| `scripts/test.sh smoke` | 煙測；伺服器未啟動 → 非 0 |
| `scripts/test.sh scenario` | 整合 |
| `scripts/test.sh e2e` | E2E |
| `scripts/test.sh all` | 四層，全部跑完再彙總 exit code |

## 5. 入口對照表

| ID | 項 | 層級 | 鎖定入口 |
|----|----|------|----------|
| | | | |

## 6. 資料與機密

- 測試資料前綴 `<prefix>_<uniq>_`，tearDown 清理；禁止硬刪共用帳號。
- 帳密只放環境變數或 gitignore 檔；報告與 log 不寫明文密碼。

## 7. known-debt 政策

`tests/known-debt.md` 分「阻斷項」（正在失敗的真缺陷，保持紅燈，不得改 skip）與「舊債」（不阻斷主流程）。每筆含：項目、原因、日期。不得用它跳過未實作的主路徑測試。

## 8. 通過判定

✅ 完成定義齊備、四層實跑 exit 0；🟡 齊備但仍有登記的阻斷項；🔴 缺項或有未登記失敗。
```
